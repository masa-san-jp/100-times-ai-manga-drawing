## 指摘と修正

| 指摘 | 対応と回帰検証 |
| --- | --- |
| 破損・欠損した候補の再取得で利用可否が戻らない | hash照合と原子的再保存、同じ候補IDを回復。raw/display/thumbの3種で再submitゼロを確認 |
| 旧失敗jobの再試行で同ページの新roundと並行する | transaction内で他roundの非終端jobを検査して409 |
| import再送が別作品を作る | DB成功receiptを期限検査より先に照合。同token再送と期限後replayを検証 |
| 結果キー異常で照合とdownloadを繰り返す | 結果異常は手動回収へ。完了済みremoteを同時実行枠から除外 |
| doctorと期限掃除の不足 | 書込probe、FK/画像hash検査、期限切れstagingだけの掃除を追加 |
| pollが編集の版番号を最新にして競合をすり抜ける | 編集開始版を固定。2タブ試験で409と未保存入力保持を確認 |
| 応答喪失後の再操作で別キーを作る | 操作payloadとkeyをsessionStorageに保存。commit後に通信を切ってreload再送してもbatch/jobが増えない |
| 再送待ちの間の新編集を消す | 実送信payloadと比較し新編集を保持。最新保存内容を確認して明示的に重ねて保存できる |
| pollが復旧入力を消す | 編集中の外部IDと送信枠を保持し、照合成功後に表示更新 |
| 除外理由と過去候補の送信全文が見えない | plan除外理由、候補に対応する保存済プロンプトと却下理由を表示 |

ライトとダーク、1280pxと360pxの画像も確認した。最終判断は親担当が全40試験、性能測定、両レビューを合わせて行った。

このPASSはモック版の完成条件に対する判定である。実際の画像生成API、実モデルの作画品質、外部公開環境に対する合格判定ではない。
