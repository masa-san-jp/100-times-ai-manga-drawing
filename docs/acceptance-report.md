# v1モック版の受け入れ結果

実施日：2026年10月18日。結果：モック版完成・実API未接続。

## 実行結果

macOS arm64、Python 3.13.13。依存はuv.lockに固定。FastAPI 0.143.3、Starlette 1.8.0、Pillow 13.0.0、Pydantic 2.14.1、pytest 9.1.1、Playwright 1.64.0で検証した。

| 検証 | 結果 |
| --- | --- |
| Ruff checkとformat | 成功 |
| OpenAPI生成 | 成功、31パス |
| pytest 全体 | 40 passed、32.44秒 |
| うちChromium | 5 passed。UI担当が独立実行しても成功 |
| バックエンド試験 | 35 passed。信頼性担当が独立実行しても成功 |
| 300ページ×3候補 | 900成功、900候補、submit 1回、初回一覧40件 |
| 同負荷の処理時間 | 4.909秒（このマシンの模擬画像に対する値） |
| 同負荷の最大RSS | 74.28MiB、512MiB目標以下 |
| 外部画像生成API | 使用なし、課金なし |

StarletteのTestClientがhttpxからhttpx2への移行を案内するdeprecation warningが1件ある。テスト失敗ではなく、実行時の画像生成接続にも関係しない。依存更新時に対応を確認する。

## UIの目視確認

artifacts/screenshotsへ設定画面、一覧、詳細のライト/ダーク、詳細の1280/360pxを保存して確認した。原稿画像の色はテーマで変更せず、狭い画面では比較を縦並び、主要操作を全幅にする。

文字と主要操作の色はCSS変数で管理する。操作にはfocus-visible、入力ラベル、状態文字を用意し、色だけで合否を区別しない。アクセシビリティ適合の正式認証を行ったという意味ではない。

## 再実行

[運用手順](operations.md)の検証コマンドを使う。Chromium試験はlocalhostへのbind権限が必要。今回の環境では `PLAYWRIGHT_BROWSERS_PATH=/private/tmp/manga-browsers` を指定した。通常の環境では `uv run playwright install chromium` の標準保存先で実行できる。

性能測定の生データはartifacts/benchmark.json、スクリーンショットはartifacts/screenshotsへ出力する。これらの生成物はGit管理せず、試験で再生成できる。

## 残る制限

実API、カラー、複数ユーザー、外部公開は未対応。入力はフォルダーと複数ファイルで、ZIP取り込みは行わない。モック候補は識別用の試験画像であり、作者のネームをAIで描き直した画像ではない。

実API対応時にはSDKの暗黙再試行、実schema、利用枠、期限、課金、作画品質をI15で検証する。
