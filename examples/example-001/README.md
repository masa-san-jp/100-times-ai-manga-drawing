## 確認できたこと・残る問題

全8件について、①リファレンス採用後の生成であること、②送信したリファレンスと上の4画像が一致すること、③掲載画像とアプリの候補画像が一致すること、④送信本文と原文が一致することを生成記録で照合しました。一方、3ページの集中線追加、6ページの小さい人物の顔の省略などは残っています。原文を送信できたことと、画像が作者の要求を満たすことは区別します。作者の採否は変更していません。候補画像の実寸は1792×2400pxで、原文指定の1410×1920pxとは異なります。採用画像の書き出し時にアプリが1410×1920pxへ整形しますが、ここには整形前の候補を掲載しています。

## 入力資料

| フォルダー | 内容 |
| --- | --- |
| キャラクタースケッチ | 4人の元資料 |
| キャラクターリファレンス | 採用した4人の設定画・生成指示 |
| ネーム | 8ページのコマ割り・セリフ・配置 |
| 作画指示書 | 8ページの画像による指示 |

## アプリでの手順

1. このフォルダーを選び、manifest.jsonと入力資料を登録。
2. キャラクター画面でリファレンスを生成し、使用する画像を採用。
3. ページ一覧から未生成ページをまとめて生成。原文はmanifest.jsonのbase_promptから登録されます。
4. ページごとに採用・要修正を判定。原文は参照専用です。詳細画面の「作画指示」「修正内容」でページ固有の指示を追記。
5. 要修正ページを再生成し、採用画像を書き出す。

テイクは各ページの生成回です。今回の再生成も通常の候補追加処理を使い、元のページ・採用リファレンスを維持しています。旧手順の公開画像は撤去し、公開フォルダーには最新のテイク3を掲載しています。
